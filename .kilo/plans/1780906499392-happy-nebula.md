# Plan: Allow Identification-Only Brands to Define & Collect Tokens

## Problem

Identification-only brands (e.g. `ID_ONLY_BRAND`) currently finalize immediately after party resolution — **no tokens are collected**. The user cannot define which tokens to ask for during identification. Even when ANI maps to a single party, the flow skips directly to `AUTHENTICATED at NONE` without prompting for any identifying credentials.

The expected behavior is: identification-only brands should be able to **optionally define token rules** (under `levelRules[NONE]`) that are asked from the caller, just like normal brands do. Token collection continues until all configured tokens are collected, and only then does the session finalize as `AUTHENTICATED at NONE`.

## Design Decision

Use the **existing `levelRules` structure** with a special `NONE` level key to define identification tokens. This reuses the proven `evaluateProgress()` / `submitToken()` pipeline instead of building a parallel system. Identification-only brands without `levelRules[NONE]` continue to work exactly as before (backward compatible).

### 2. `AuthenticateService.start()` — Don't skip initial tokens for ID-only with rules

**File:** `src/main/java/com/yourco/ivr/service/AuthenticateService.java`, lines 127-131

**Current:**
```java
if (config.isIdentificationOnly()) {
    return engine.onPartyResolved(session, config);
}
```

**Change to:** If identification-only AND `NONE`-level rules exist, process initialTokens before calling `onPartyResolved()`; otherwise, call `onPartyResolved()` immediately (backward compatible).

```java
if (config.isIdentificationOnly()) {
    if (config.getLevelRules() != null && config.getLevelRules().containsKey(AuthLevel.NONE)) {
        if (req.getInitialTokens() != null && !req.getInitialTokens().isEmpty()) {
            for (Map.Entry<TokenType, String> entry : req.getInitialTokens().entrySet()) {
                AuthenticateResponse tokenResponse = engine.submitToken(
                    session.getSessionId(), entry.getKey(), entry.getValue());
                if (tokenResponse.getStatus() == SessionStatus.FAILED
                        || tokenResponse.getStatus() == SessionStatus.REDIRECT_TO_AGENT) {
                    return tokenResponse;
                }
            }
            IvrSession updatedSession = sessionRepo.getOrThrow(session.getSessionId());
            return engine.evaluateProgress(updatedSession, config);
        }
    }
    return engine.onPartyResolved(session, config);
}
```

### 3. `AuthEngine.onPartyResolved()` — Gate to `evaluateProgress()` when NONE rules exist

**File:** `src/main/java/com/yourco/ivr/engine/AuthEngine.java`, lines 320-325

**Current:**
```java
public AuthenticateResponse onPartyResolved(IvrSession session, BrandAuthConfig config) {
    if (config.isIdentificationOnly()) {
        return finalizeIdentification(session);
    }
    return evaluateProgress(session, config);
}
```

**Change to:**
```java
public AuthenticateResponse onPartyResolved(IvrSession session, BrandAuthConfig config) {
    if (config.isIdentificationOnly()) {
        if (config.getLevelRules() != null && config.getLevelRules().containsKey(AuthLevel.NONE)) {
            return evaluateProgress(session, config);
        }
        return finalizeIdentification(session);
    }
    return evaluateProgress(session, config);
}
```

### 5. `AuthEngine.submitToken()` — Null-safe levelRules access

**File:** `src/main/java/com/yourco/ivr/engine/AuthEngine.java`, lines 168-171

**Current:**
```java
LevelRule ruleCtx = config.getLevelRules().get(session.getTargetLevel());
```

**Change to:** Guard against null `levelRules` — when an identification-only session has no `levelRules`, accessing `.get()` NPEs. This path shouldn't be reachable in normal flow (the session finalizes at start), but is a safety guard for edge cases:
```java
LevelRule ruleCtx = config.getLevelRules() != null
    ? config.getLevelRules().get(session.getTargetLevel()) : null;
```

Similarly guard other `config.getLevelRules().get(...)` calls in `submitToken()` methods: `resolveBackupToken()` (line 454), `findRequiredTokenForSlot()` (line 488), `handleFailure()` (line 519).

## Edge Cases Covered

1. **ID-only brand with NO `levelRules`** → `onPartyResolved()` calls `finalizeIdentification()` immediately (backward compat)
2. **ID-only brand WITH `NONE` rules** → `onPartyResolved()` calls `evaluateProgress()`, prompts for tokens
3. **ID-only brand + multiple parties (disambiguation)** → disambiguation runs, resolves to single party, then prompts for identification tokens
4. **ID-only brand + initialTokens** → tokens processed before first prompt; if they satisfy all rules, finalize immediately
5. **ID-only brand + token retries/path switching** → works via existing `handleFailure()`/`advanceToNextPathOrFail()` logic
6. **ID-only brand + backup tokens** → `resolveBackupToken()` maps SSN_LAST4 to PIN slot etc.
7. **ID-only brand + escalation** → still rejected (unchanged guard in `escalate()`)
8. **Null `levelRules` safety** → all `config.getLevelRules().get(...)` calls guarded

## Normalizing targetLevel

In `AuthenticateService.start()`, for identification-only brands: **always force `targetLevel=NONE`** regardless of what the request specifies, so the engine always looks up the correct rule.

## AUTHENTICATED guard in submitToken()

Add an early return in `submitTokenWithCaller()` for sessions already in `AUTHENTICATED` or `FAILED` state to prevent meaningless re-submission.
